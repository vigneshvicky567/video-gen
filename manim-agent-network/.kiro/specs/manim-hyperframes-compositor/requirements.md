# Requirements Document

## Introduction

This feature replaces the existing dumb ffmpeg-based assembler service with a HyperFrames-based compositor pipeline. The new pipeline introduces three major capabilities:

1. **HyperFrames Compositor** — owns the full 1920×1080 canvas. Manim render clips become content panels inside a declarative HTML composition that is rendered to MP4 by `npx hyperframes render` in a single deterministic pass.
2. **Image Fetcher Node** — a new LangGraph node that extracts keywords from each scene's `narration_text` and `visual_description`, fetches contextually relevant images from Pexels (primary) and Wikimedia Commons (fallback), and downloads them per scene into the shared workspace.
3. **Audio/Video Sync Fix** — `ffprobe` is used to measure the real duration of every Manim render clip and every TTS audio file. Exact scene start times are computed by accumulating actual durations, eliminating audio bleed and overlap.

The LangGraph pipeline is extended: `voiceover → image_fetcher → assembler`. The assembler service is replaced end-to-end; all other services remain unchanged.

---

## Glossary

- **Compositor**: The new assembler service that uses HyperFrames to produce the final MP4.
- **HyperFrames**: A declarative HTML-to-video rendering tool invoked via `npx hyperframes render`.
- **HyperFrames_HTML**: The HTML composition document generated by an LLM and consumed by HyperFrames.
- **Image_Fetcher**: The new LangGraph node and backing FastAPI service responsible for fetching context images per scene.
- **Duration_Prober**: The component within the Compositor that uses `ffprobe` to measure real media durations.
- **LLM_Composer**: The component within the Compositor that calls an LLM to generate the HyperFrames_HTML document.
- **Pexels_Client**: The HTTP client that queries the Pexels API for royalty-free images.
- **Wikimedia_Client**: The HTTP client that queries the Wikimedia Commons API as a fallback image source.
- **ScenePlan**: The existing shared schema with fields `scene_id`, `narration_text`, `visual_description`, `estimated_duration_seconds`.
- **SceneTimingRecord**: A new data structure holding `scene_id`, `render_path`, `audio_path`, `actual_video_duration_seconds`, `actual_audio_duration_seconds`, and `start_time_seconds`.
- **LangGraphState**: The existing shared TypedDict that flows through the LangGraph pipeline.
- **Workspace**: The shared Docker volume mounted at `/workspace`.

## Requirements

### Requirement 1: Duration Probing

**User Story:** As a pipeline operator, I want the compositor to measure the real duration of every Manim render clip and TTS audio file, so that scene start times are computed from actual data and audio never bleeds into the next scene.

#### Acceptance Criteria

1. WHEN the Compositor receives an assemble request, THE Duration_Prober SHALL invoke `ffprobe` on each file listed in `render_paths` and `audio_paths` to obtain its duration in seconds.
2. WHEN `ffprobe` returns a duration for a media file, THE Duration_Prober SHALL store the result as a floating-point value with millisecond precision (three decimal places).
3. IF `ffprobe` exits with a non-zero return code for a given file, THEN THE Duration_Prober SHALL raise an assembly error that includes the file path and the `ffprobe` stderr output.
4. WHEN all per-scene durations have been probed, THE Duration_Prober SHALL compute `start_time_seconds` for each scene by accumulating the maximum of `actual_video_duration_seconds` and `actual_audio_duration_seconds` from all preceding scenes in ascending `scene_id` order.
5. THE Duration_Prober SHALL produce one `SceneTimingRecord` per scene containing `scene_id`, `render_path`, `audio_path`, `actual_video_duration_seconds`, `actual_audio_duration_seconds`, and `start_time_seconds`.
6. FOR ALL valid sets of `SceneTimingRecord` lists, the `start_time_seconds` of scene N SHALL equal the sum of `max(actual_video_duration_seconds, actual_audio_duration_seconds)` for all scenes with `scene_id` less than N (round-trip accumulation property).

### Requirement 2: Image Fetcher Service

**User Story:** As a content creator, I want each scene to have contextually relevant images fetched automatically, so that the final video includes visual context beyond the Manim animation.

#### Acceptance Criteria

1. WHEN the Image_Fetcher receives a fetch request for a scene, THE Image_Fetcher SHALL extract between 1 and 5 keywords from the scene's `narration_text` and `visual_description` using an LLM call.
2. WHEN keywords have been extracted, THE Pexels_Client SHALL query the Pexels API using those keywords and retrieve up to 3 image results per scene.
3. IF the Pexels_Client returns zero results for a scene, THEN THE Wikimedia_Client SHALL query the Wikimedia Commons API using the same keywords and retrieve up to 3 image results.
4. WHEN an image URL has been selected, THE Image_Fetcher SHALL download the image file to `{WORKSPACE_DIR}/temp/{job_id}/images/scene_{scene_id}/` and record its absolute path.
5. IF both the Pexels_Client and the Wikimedia_Client return zero results for a scene, THEN THE Image_Fetcher SHALL record an empty image list for that scene and continue without raising an error.
6. THE Image_Fetcher SHALL complete fetching for all scenes before returning a response, and the response SHALL include a mapping of `scene_id` to a list of absolute image file paths.
7. WHEN the Image_Fetcher downloads an image file, THE Image_Fetcher SHALL verify the downloaded file is a valid JPEG or PNG by checking its magic bytes, and IF the file fails validation, THEN THE Image_Fetcher SHALL discard it and attempt the next available result.

---

### Requirement 3: Image Fetcher LangGraph Node

**User Story:** As a pipeline operator, I want image fetching to be a first-class step in the LangGraph pipeline, so that context images are available to the compositor without manual intervention.

#### Acceptance Criteria

1. THE LangGraphState SHALL include a new field `image_paths` of type `Dict[int, List[str]]` mapping `scene_id` to a list of absolute image file paths.
2. WHEN the `voiceover_node` completes successfully, THE LangGraph pipeline SHALL route to the `image_fetcher_node` before routing to the `assembler_node`.
3. WHEN the `image_fetcher_node` executes, THE image_fetcher_node SHALL call the Image_Fetcher service at `http://image-fetcher:8006/fetch` with the current `job_id`, `script`, and `audio_paths`.
4. WHEN the Image_Fetcher service returns a successful response, THE image_fetcher_node SHALL merge the returned `image_paths` mapping into `LangGraphState` and set `status` to `"image_fetching"`.
5. IF the Image_Fetcher service returns an HTTP error, THEN THE image_fetcher_node SHALL set `overall_error` in `LangGraphState` and route to the `failed` node.

### Requirement 4: LLM-Generated HyperFrames HTML Composition

**User Story:** As a content creator, I want the compositor to generate a rich, properly timed HyperFrames HTML document using an LLM, so that the final video has professional layout with title cards, lower thirds, Manim panels, and context images.

#### Acceptance Criteria

1. WHEN all `SceneTimingRecord` entries and `image_paths` are available, THE LLM_Composer SHALL send a prompt to the configured LLM containing: the script title, per-scene `narration_text`, per-scene `visual_description`, per-scene `actual_video_duration_seconds`, per-scene `actual_audio_duration_seconds`, per-scene `start_time_seconds`, and per-scene image file paths.
2. WHEN the LLM returns a response, THE LLM_Composer SHALL extract a single valid HTML document from the response and write it to `{WORKSPACE_DIR}/temp/{job_id}/composition.html`.
3. THE LLM_Composer SHALL instruct the LLM to place each Manim render clip as a video element within a content panel sized no larger than 1280×720 pixels inside the 1920×1080 canvas.
4. THE LLM_Composer SHALL instruct the LLM to place each scene's audio track on the timeline starting at the scene's `start_time_seconds`.
5. THE LLM_Composer SHALL instruct the LLM to include a title card for the script title at `start_time_seconds` 0.
6. THE LLM_Composer SHALL instruct the LLM to include a lower-third text overlay for each scene displaying the scene's `narration_text` truncated to 120 characters, timed to the scene's `start_time_seconds`.
7. IF the LLM response does not contain a parseable HTML document, THEN THE LLM_Composer SHALL retry the LLM call up to 2 additional times before raising an assembly error.
8. THE LLM_Composer SHALL produce a composition where the total timeline duration equals the `start_time_seconds` of the last scene plus the `max(actual_video_duration_seconds, actual_audio_duration_seconds)` of the last scene.

---

### Requirement 5: HyperFrames Render Execution

**User Story:** As a pipeline operator, I want the compositor to invoke `npx hyperframes render` on the generated HTML document, so that the final MP4 is produced in a single deterministic pass without intermediate ffmpeg concatenation.

#### Acceptance Criteria

1. WHEN `composition.html` has been written to disk, THE Compositor SHALL invoke `npx hyperframes render --input {composition_html_path} --output {final_output_path} --width 1920 --height 1080` as a subprocess.
2. WHEN `npx hyperframes render` exits with return code 0, THE Compositor SHALL verify that the output file exists at `final_output_path` and has a file size greater than 0 bytes.
3. IF `npx hyperframes render` exits with a non-zero return code, THEN THE Compositor SHALL raise an assembly error that includes the process stdout and stderr.
4. IF the output file does not exist or has a file size of 0 bytes after a successful exit code, THEN THE Compositor SHALL raise an assembly error indicating an empty output.
5. THE Compositor SHALL write the final MP4 to `{WORKSPACE_DIR}/outputs/{job_id}_final.mp4`.
6. THE Compositor SHALL expose a `/assemble` POST endpoint accepting the existing `AssemblerRequest` schema extended with a `scene_plans` field of type `List[ScenePlan]` and an `image_paths` field of type `Dict[int, List[str]]`.

---

### Requirement 6: Compositor Service Infrastructure

**User Story:** As a platform engineer, I want the new compositor to run as a Docker service in the existing compose stack, so that it integrates without disrupting the other services.

#### Acceptance Criteria

1. THE Compositor SHALL run as a FastAPI service on port 8005, replacing the existing assembler service at the same address so that the orchestrator requires no URL changes.
2. THE Compositor's Docker image SHALL include `ffprobe`, `ffmpeg`, `Node.js` (version 18 or later), and `npx` so that all runtime dependencies are available without additional installation steps.
3. THE Compositor's Docker image SHALL install the `hyperframes` npm package at a pinned version during image build.
4. THE Compositor SHALL accept the environment variables `OPENAI_API_KEY` and `COMPOSITOR_LLM_MODEL` (defaulting to `"gpt-4o"`) for LLM composition.
5. THE Compositor SHALL mount the shared Workspace volume at `/workspace` and write all intermediate files under `{WORKSPACE_DIR}/temp/{job_id}/`.
6. WHERE `PEXELS_API_KEY` is set in the environment, THE Image_Fetcher SHALL authenticate Pexels API requests using that key.
7. WHERE `PEXELS_API_KEY` is not set in the environment, THE Image_Fetcher SHALL skip the Pexels query and proceed directly to the Wikimedia fallback.

---

### Requirement 7: Assembler Request and State Schema Extensions

**User Story:** As a pipeline developer, I want the shared schemas and LangGraph state to carry the new data needed by the compositor, so that all services share a single source of truth.

#### Acceptance Criteria

1. THE `AssemblerRequest` schema SHALL be extended with a `scene_plans` field of type `List[ScenePlan]` and an `image_paths` field of type `Dict[int, List[str]]`, both required.
2. THE `LangGraphState` TypedDict SHALL be extended with an `image_paths` field of type `Dict[int, List[str]]`.
3. WHEN the `assembler_node` in the LangGraph graph constructs the assemble request, THE assembler_node SHALL populate `scene_plans` from `state["script"]["scenes"]` and `image_paths` from `state["image_paths"]`.
4. THE `SceneTimingRecord` SHALL be defined as a Pydantic model in `shared/schemas/common.py` with fields: `scene_id: int`, `render_path: str`, `audio_path: str`, `actual_video_duration_seconds: float`, `actual_audio_duration_seconds: float`, `start_time_seconds: float`.
5. FOR ALL valid `SceneTimingRecord` instances, `start_time_seconds` SHALL be greater than or equal to 0.0.

---

### Requirement 8: Parser and Serialization — HyperFrames HTML Round-Trip

**User Story:** As a pipeline developer, I want the LLM-generated HyperFrames HTML to be validated and round-tripped, so that malformed compositions are caught before invoking the renderer.

#### Acceptance Criteria

1. WHEN `composition.html` is written to disk, THE Compositor SHALL parse it with an HTML parser to confirm it is well-formed before invoking `npx hyperframes render`.
2. IF the HTML parser raises a parse error, THEN THE Compositor SHALL treat the document as invalid and trigger the LLM retry logic defined in Requirement 4, Criterion 7.
3. THE Compositor SHALL extract all `src` attribute values from `<video>` and `<audio>` elements in the parsed HTML and verify that each referenced file path exists on disk before invoking the renderer.
4. IF any referenced media file path does not exist on disk, THEN THE Compositor SHALL raise an assembly error listing the missing paths.
5. FOR ALL valid `composition.html` documents, parsing the HTML, serializing it back to a string, and parsing again SHALL produce a DOM tree with the same number of `<video>`, `<audio>`, and `<img>` elements as the original parse (round-trip structural equivalence property).
