# manim-agent-network — System Audit & Remediation Spec

**Date:** 2026-07-05
**Scope:** Backend only (frontend explicitly out of scope per operator).
**Method:** 18 parallel finder agents mapped every backend service across 8 dimensions (correctness, weak-points, wrongly-mapped functions, security, dead-code, LLM-usage, tests, config). 334 raw findings were produced; 30 were independently adversarially verified against the source before the audit run hit the org spend cap (verification of the remaining medium/low findings was cut short — see §11). This document synthesizes all findings, deduplicated, and leads with the operator's two stated pains: **the pipeline is fragile**, and **the generated content is low quality.**

---

## 1. Executive Summary

The system is a LangGraph state machine (orchestrator) fanning out over HTTP to six FastAPI microservices — script-writer, code-generator, validator, image-fetcher, voiceover, compositor — plus a public web-tier. Untrusted user prompts drive an LLM that emits Python (Manim) and HTML (HyperFrames) code, which is then **executed** by the validator via `manim render` in a subprocess.

**Health verdict: structurally thoughtful, operationally fragile, and quality-blind.** The resilience scaffolding is real (retry caps, bounded fan-out, graceful scene-dropping, resume-on-restart, wall-clock timeout, subprocess-group kill in the compositor). But it is undermined by a broken persistence contract, several unbounded hangs, fail-open QA, and a code-execution sandbox that is a trivially-bypassable denylist. On quality, the prompts are strong on mechanical correctness and almost silent on pedagogy — there is no quality rubric, no HyperFrames few-shot, no self-critique, and the only feedback that ever reaches the generator is "did it render," never "is it good."

**Finding counts (334 total):** 10 critical · 57 high · 121 medium · 146 low. By category: 161 weak-point · 75 correctness · 31 improvement · 17 test-gap · 16 wrongly-mapped · 16 security · 18 dead-code/over-engineering.

**Top 5 risks**

1. **Admin API is fully unauthenticated** — `require_admin()` returns a hard-coded admin `Principal`, ignoring the request entirely. Every `/admin/*` endpoint (list all jobs/users, cost data, **set anyone's role to admin**) is open to the internet. *(security, critical, `web-tier/app/auth.py:67`)*
2. **Code-execution sandbox is bypassable** — the validator's AST denylist is the only runtime gate and misses dunder/reflection escapes (`().__class__.__bases__[0].__subclasses__()`, `getattr` not blocked). Attacker-influenced generated code runs with full interpreter privileges plus API keys in the env. The *stronger* checker (`check_manim_security`) is **dead code, never called.** *(security, critical, `validator/app/main.py:420`, `code-generator/app/sanitizer.py:25`)*
3. **Resume is silently broken** — every per-scene state dict is int-keyed, but JSON serialization stringifies keys on every DB round-trip. Only 1 of 7 dicts re-coerces on load, so on resume already-rendered scenes look unrendered and the whole film re-renders (or worse, is unusable). This defeats the entire idempotency design. *(correctness, critical, `orchestrator/app/main.py:75,128`, `core/graph.py:382`)*
4. **QA fails open** — vision-inspect and HF-lint return "pass" on any tooling error, so when the vision model or lint container is down, blank/black/broken scenes ship in a "completed" film. The operator sees green; the user sees black. *(weak-point, high, `validator/app/main.py:290,627`)*
5. **Content has no quality loop** — a scene that renders but is dull, off-topic, or visually generic is accepted on attempt 1; the retry prompt literally says "keep the scene's content and design intent." *(weak-point, critical, `code-generator/app/main.py:450`)*

**Pain A — "the pipeline is fragile":** Confirmed. Fragility concentrates in ~8 high-frequency modes: the resume/JSON-key bug (#3), missing/coarse timeouts that hang the graph, LLM garbage (None/truncated content) crashing downstream parsing, a single service blip burning all retries and killing the job, and fail-open QA masking broken output. See §2.

**Pain B — "the generated content is shit":** Confirmed and diagnosable. Root causes are structural, not bad luck: no few-shot for the majority (HyperFrames) path, a "council" that map-reduces sections into tonal mush with no best-of selection, a reviewer that critiques a 200-char truncation, a clamp that silently overshoots pacing, image relevance kept in coarse order below a "loosely related" floor, no factual grounding, and no self-critique. See §3.

## 2. WHY THE PIPELINE IS FRAGILE

The graph itself is well-built. Fragility lives at the seams: persistence, timeouts, LLM output validation, and infra-vs-content error conflation. Ranked by likely firing frequency.

### 2.1 Single points of failure & silent breakage

- **[CRITICAL] Resume/persistence contract is broken (JSON int→str keys).** `render_paths`, `code_paths`, `retry_counts`, `error_logs`, `audio_paths`, `previous_code`, `image_paths` are all int-keyed in `graph.py`, but persisted as JSON where object keys are always strings. Only `image_paths` re-coerces on load (`graph.py:205` — proving the author knows). On every resume, `validation_router`'s `if scene_id not in render_paths` (int vs str) reports every rendered scene as missing. Fix: one `_coerce_scene_keys(state)` helper applied at load, or standardize on str keys everywhere. Add a JSON round-trip test. *(`orchestrator/app/main.py:75,128,384`; `core/graph.py:382`)*

- **[HIGH] One service blip fails the whole job.** `_post` calls `raise_for_status()`; a 502 from a restarting validator or a `ConnectError` from a briefly-down service is caught as a *per-scene* failure and burns the shared retry budget (cap 5). If any service OOM-restarts, all in-flight scenes exhaust retries against it and `validation_router` routes to `failed`/`partial`. Infra-transient errors are counted identically to LLM-produced bad code. Fix: classify exceptions in `_post` — `ConnectError`/`ReadTimeout`/5xx are infra-transient, retry with backoff or fail-fast with "service X unavailable"; do not consume per-scene quality retries. Add a `/health` gate before fan-out. *(`core/graph.py:32,117,356,392`)*

- **[HIGH] LLM garbage flows unvalidated into downstream parsing.** `_NimCompletions` builds `content` from `message.get('content')` with no `None` guard; `_ClaudeCompletions` sets `text=''` on a missing block and only *logs* a refusal. There is **no `finish_reason=='length'` check anywhere** — a truncated response produces invalid JSON that looks like a successful call, and the next stage crashes with `JSONDecodeError` surfaced as a generic node failure. Fix: raise a typed retryable error on falsy content, on `refusal`/`content_filter`, and on `length` truncation; return `finish_reason` so callers detect truncation. *(`shared/llm_client.py:292,395,467`)*

- **[HIGH] Fail-open QA ships broken videos as "completed."** `_vision_inspect_manim` returns `(True,'')` on any error (no client, ffprobe fail, all vision calls fail) and needs a 2-of-3 "broken" majority to fail — so a render where 2 frames couldn't be sampled *can never fail*. `_lint_hyperframes_remote` returns pass when the lint service is unreachable (unless `COMPOSITOR_FAIL_CLOSED`). `_check_hf_visual_issues` swallows its own exception. Combined: when the QA layer can't run, blank scenes pass. Fix: fail-**closed** on high-signal checks (vision says broken, lint says error); fail-open only for genuine tooling-unavailable, and record `qa_skipped` scene ids into job state so a "completed" film with unverified scenes is visibly flagged. *(`validator/app/main.py:235,289,623`)*

### 2.2 Missing timeouts, unbounded loops, and hangs

- **[HIGH] Validator manim subprocess uses parent-only kill, not process-group kill.** `_run_manim_subprocess` does `proc.kill()` on timeout, but manim spawns `latex`/`dvisvgm`/`ffmpeg` children that inherit the stdout/stderr pipe; killing only the parent can leave children writing to the pipe so `communicate()` in the except branch never returns cleanly — a wedged render holds a semaphore slot and stalls the validator. **The compositor already fixed this exact bug** with `os.setsid` + `os.killpg` (`compositor/main.py:139,146`); the validator never got the fix. Fix: mirror it — `Popen(preexec_fn=os.setsid)`, `os.killpg(os.getpgid(proc.pid), SIGKILL)` on timeout. *(`validator/app/main.py:24,719`)*

- **[MEDIUM] Compositor `/assemble` dedup future can deadlock forever.** A second caller does `await existing_fut` with **no timeout**, and the future is resolved only in the creating request's success/except branches (no `finally`). If the creator is cancelled (client disconnect / shutdown) before those branches, the future is never set — **all** future `/assemble` for that `job_id` deadlock on a dead future. Fix: `asyncio.wait_for` with a bound, resolve/pop in a `finally`. Also `asyncio.get_event_loop()` is deprecated in a coroutine — use `get_running_loop()`. *(`compositor/app/main.py:292`)*

- **[MEDIUM] Blocking subprocess on the event loop.** `_has_audio_stream`, `_normalize_audio_streams`, and the concat sanity-check `sum(probe_duration(...))` call `subprocess.run` synchronously inside the async `/assemble` handler, freezing `/health` and `/lint` for the whole fleet during assembly (the compositor's own other paths offload to threads). Fix: wrap in `asyncio.to_thread`. *(`compositor/app/main.py:193,285`)*

- **[MEDIUM] Wall-clock timeout doesn't cancel in-flight renders.** `run_pipeline` wraps the graph in `asyncio.wait_for`, but a render already dispatched as a synchronous HTTP POST inside a node is not cancelled; the downstream subprocess runs to its own much-larger timeout, leaking CPU/GPU for a job already marked failed. Fix: POST `/cancel` to validator/compositor on wall-clock timeout; never let a per-request HTTP timeout exceed remaining wall-clock budget. *(`orchestrator/app/main.py:228,260`)*

- **[MEDIUM] Render-timeout heuristic is miscalibrated.** `_compute_timeout` counts every `*.play` attribute call — matching `self.play` but also `audio.play()`, `.replay()`, etc. — and **under-counts** many animations inside one `self.play(*anims)`. Under-count → render blows the computed budget → false "timed out" that burns retries and is fed to the retry prompt as if the *code* were bad. Fix: restrict to `self.play`, weight by `run_time`/arg count, and surface "timed out" distinctly from "bad code." *(`validator/app/main.py:97`)*

### 2.3 Multi-worker / operational assumptions

- **[MEDIUM] Driving-lock and cancel-flag are per-process sets.** `_DRIVING`/`_CANCEL` live in one process. With >1 uvicorn worker or >1 replica, two workers can drive the same job concurrently, racing `db.update_job` writes; a cancel hitting worker A does nothing if the driver is in worker B. Fix: move to a shared DB column (`driver_owner`/`cancel_requested` with claim/heartbeat) or Redis; at minimum assert worker-count==1 at startup and document it loudly. *(`orchestrator/app/main.py:28,116,389`)*

- **[LOW] Orphan-resume trusts `final_output_path` without checking the file exists.** A job is healed to `completed` because the path string is truthy in persisted state; if the file was never fully written or was later cleaned up, the job is green while `/video/{job}` 404s. Fix: `os.path.exists` + `st_size>0` before healing, else re-drive the assembler. *(`orchestrator/app/main.py:57`)*

- **[LOW] Shared-key RPM pacing is process-local.** `_get_semaphore` never recreates on loop change (contradicting its own docstring), and the RPM math assumes one process owns the per-key budget while the comment admits N services share keys (hand-tuned `NVIDIA_RPM=40/N`). Adding a service silently breaches the account RPM → everything 429s → burns per-scene retries (compounds §2.1). Fix: shared token-bucket limiter, or auto-derive the per-service budget. *(`shared/llm_client.py:112,149`)*

## 3. WHY THE GENERATED CONTENT IS LOW QUALITY

The prompts enforce *mechanical* correctness well (forbidden APIs, visibility traps, layout safe-zones) but are nearly silent on *pedagogical and visual* quality. There is no rubric, no HyperFrames example, no self-critique, and no quality signal in the feedback loop. Several correctness bugs compound the problem.

### 3.1 No quality signal anywhere in the loop

- **[CRITICAL] Renderability is the only gate; quality is never measured.** The sole signal that flows into a regeneration is `error_log`/`previous_code` — a crash, syntax error, or "render appears empty/broken/cluttered." Nothing scores whether a scene *teaches the concept*, has good hierarchy, or matches the narration. The retry prompt says *"Fix the error while keeping the scene's content and design intent"* — i.e. preserve the mediocre content. Fix: add a self-critique pass (cheap LLM/vision rubric 1–5 on visual-matches-narration, legibility/hierarchy, insight-beyond-words); below threshold → regenerate with the critique as `error_log`. This is the single highest-leverage quality change. *(`code-generator/app/main.py:450,639`)*

- **[HIGH] No factual grounding.** Writers/planner get only the topic string and are told to "explain the topic clearly" — no sources, no instruction to avoid inventing dates/numbers/names, and the reviewer never checks accuracy. For educational video this is a credibility failure: the model confidently narrates plausible-but-wrong facts. Fix: add an accuracy directive; optionally a retrieval step (deep-research/web tools are available) to ground scripts; add a fact-check axis to the reviewer. *(`script-writer/app/council.py:194`)*

### 3.2 The "council" doesn't deliberate

- **[HIGH] Council is a naive map-reduce, not a council.** `_full_council` writes one section per writer in isolation (only topic+goal) and `scenes.extend`s whatever each returns — no cross-section coherence, no candidate-and-pick, no scoring. Transitions, recurring metaphors, terminology, and difficulty ramp are uncoordinated; a failed section silently returns `[]`, leaving a narrative hole. Fix: either generate 2–3 candidate scripts and have the reviewer pick the best (a real council), or give each writer neighbor-section context + a shared style/terminology contract plus a final coherence stitch; make a failed section a hard retry, not a gap. *(`council.py:281`)*

- **[HIGH] The one reviewer is blindfolded.** `_reviewer` sees `narration_text[:200]` and **no** `visual_description`, yet is asked to judge narration quality and scene-type fit. Most narration problems (rambling, repetition, jargon) live past char 200 or in the visual mismatch it never sees. This is the only review pass for the whole script. Fix: send full narration + visual_description (scripts are small), emit per-scene rewrite suggestions for the worst N scenes, and always run `_writer_fix` when any high-severity issue exists. *(`council.py:320`)*

- **[LOW] Writer temperature is worst-of-both.** Section writers run `temperature=0.7`, single-sample — max variance with no selection. Fix: either drop to ~0.5 for one steady draft, or sample 2–3 at 0.8 and let the reviewer pick (best-of-N). *(`council.py:208,256`)*

### 3.3 Pacing/budget bugs actively degrade output

- **[HIGH] `clamp_durations` runs *after* the audit, so pacing silently overshoots.** Flow is audit → maybe-repair → `clamp_durations` → re-audit. `clamp` only ever *raises* each scene's est up to `ceil(narration_seconds)`, so after a repair judged "within_tolerance," the clamp pushes total duration back UP and the video overshoots — but the "within_tolerance" branch already decided not to warn. This is also why the Manim "land JUST UNDER {duration}s" pacing instruction fights the real slot length. Fix: clamp first, then audit, then decide repair/warn; re-check tolerance post-clamp. *(`council.py:430`)*

- **[MEDIUM] Repair prompt is self-contradictory.** `repair_budgets` emits both `duration_budget_s` and `word_budget`; the prompt references `estimated_duration_seconds` (name ≠ the `duration_budget_s` key) and gives two budget numbers, so the model guesses the mapping and often rewrites to the wrong target — then `clamp` overwrites it anyway. Fix: one currency — pass `{scene_id, target_words}`, instruct `estimated_duration_seconds = round(words/2.2)`. *(`council.py:382`)*

- **[LOW] Study-material duration can be lowballed then over-sectioned.** `is_study_material` is taken straight from the LLM while duration is independently clamped to `[120,1800]`; a study-material scene can end up with a 120s budget yet get routed to the heavy full-council path — a thin, over-sectioned script. Fix: raise the duration floor when `is_study_material`, or gate full-council on duration regardless. *(`analyzer.py:202`)*

### 3.4 HyperFrames (the majority path) gets the least help

- **[HIGH] HyperFrames has no few-shot; Manim does.** Manim prompts inject a concrete `_MANIM_FEW_SHOT`; the HF path ships rules + verbose prose and **zero worked example**. LLMs lean on few-shot for layout/motion taste, so HF scenes converge on the model's default "centered title + 3 bullets, power3.out fade" slop — the exact "AI-design tell" the prompt warns against. And **most scenes are HF** (`classify_scene` defaults to HF on <2 keyword hits). Fix: add 1–2 strong, distinct HF few-shots (split-screen comparison, big-number stat, annotated diagram) with varied eases and build/breathe/resolve phases; rotate by scene role. *(`code-generator/app/main.py:293,549`)*

- **[MEDIUM] Scene classifier biases everything toward text slides.** In `hybrid` mode with no `content_type`, `classify_scene` needs ≥2 hits from a 23-word math/CS keyword list to pick Manim, else HyperFrames. A genuinely visual non-math scene ("how blood flows through the heart") scores 0–1 and becomes a static text slide. Fix: trust script-writer's `content_type` as primary; broaden keywords with visual verbs (flow, diagram, network, cycle, timeline, compare) and lower the threshold when `visual_description` is non-trivial. *(`code-generator/app/main.py:118`)* — see also the wrongly-mapped duplicate-classifier finding in §5.

- **[MEDIUM] Manim few-shot teaches a forbidden anti-pattern.** `manim_rules.md` forbids `there_and_back` as an entrance ("no self-undoing slides"), yet the canonical `_MANIM_FEW_SHOT` ends with `MoveAlongPath(dot, curve, rate_func=there_and_back)` — the dot traces and snaps back, undoing itself. Models imitate the few-shot strongly. Fix: use a one-way landing ease + `self.wait()`. *(`code-generator/app/main.py:564`)*

- **[MEDIUM] The HF system prompt is bloated and self-contradictory.** The opacity/`from()` trap is stated 3×; baseline palette (`#f4f1ea`) contradicts the identity default (`#f5f5f0`); layout/typography rules are duplicated across `hf_rules.md` and the 50-line "Your Task" block. Long contradictory prompts measurably reduce instruction-following and bury the load-bearing creative direction. Fix: single-source each rule; keep "Your Task" ≤10 lines; let the per-job identity block own palette/fonts. *(`code-generator/app/main.py:136`)*

### 3.5 Imagery selection keeps loosely-related junk

- **[HIGH] Vision vet never sorts by score and keeps "loosely related" (≥5.0).** `vision_select` deliberately keeps SigLIP's coarse order and only drops below `_VISION_KEEP_MIN=5.0`, where the prompt *defines* 5 as "loosely related." So a photo the model itself rated loosely-related is kept, and can outrank a directly-relevant one because SigLIP order wins — exactly the failure this stage exists to fix. Fix: raise floor to ≥7 ("directly shows the topic"), bucket into tiers (high ≥8 / mid 6–7), prefer high, keep SigLIP order within a tier. *(`image-fetcher/app/relevance_llm.py:33,140`)*

- **[MEDIUM] Vision scoring is slow, serial, and fragile.** Sync `chat.completions.create` per image in a serial loop, `max_tokens=2000`, no timeout — tens of seconds/scene, one hung call stalls the whole scene. And `_parse_score` greps the first number anywhere, so a reasoning model's step number/year corrupts the rank. Fix: async client + `gather` + `Semaphore` + per-call timeout; `max_tokens≈10`; constrain output to a labeled score; add rejection exemplars. *(`relevance_llm.py:50,96`)*

- **[MEDIUM] Required images silently vanish.** `_image_guidance` says "You MUST use `__IMAGE_0__`," but `_inline_images` deletes any leftover/invented tokens via `sub("", html)`; if the model omits `__IMAGE_0__`, the fetched+vetted photo is dropped with no error, no retry, no log. The expensive image pipeline's output is discarded. Fix: verify each provided index was referenced; if a required image is missing, warn and inject into a default slot or feed "you omitted `__IMAGE_0__`" back for one regeneration. *(`code-generator/app/main.py:206,239`)*

## 5. Wrongly-Mapped Functions & Contract Mismatches

These are functions living in the wrong service, payloads renamed in transit, type-encoded-in-extension contracts, and state written-but-never-typed — the core of "wrongly mapped functions."

#### F20 — require_admin skips ban check and DB mirroring done by get_principal
- **Area:** web-tier  |  **Severity:** high  |  **Category:** wrongly-mapped
- **Location:** `services/web-tier/app/auth.py:67-70`
- **Problem:** Even once the bypass is removed, require_admin is defined to take Request and build a Principal itself rather than depending on get_principal like require_user does. As written (and as the 'original' comment describes) it duplicates the token-verify/ban-check/get_or_create_user logic instead of reusing get_principal, which is the single place that enforces the 'banned' suspension (auth.py:58-59). A banned admin would bypass the suspension that a banned user hits. The admin gate's responsibility (verify + ban + role) belongs layered on top of get_principal.
- **Evidence:** async def require_user(p: Principal = Depends(get_principal)) -> Principal:     return p # vs require_admin which takes Request directly and never calls get_principal
- **Fix:** Define require_admin(p: Principal = Depends(get_principal)) so it inherits token verification and the banned check, then raise 403 if p.role != 'admin'. This reuses the shared path and avoids divergent auth logic.

#### F51 — scene_plans crosses the service boundary as dicts but AssemblerRequest types it List[ScenePlan]; code defensively handles both, indicating an unresolved contract
- **Area:** compositor  |  **Severity:** low  |  **Category:** wrongly-mapped
- **Location:** `services/compositor/app/main.py:310-312, 349-356`
- **Problem:** The orchestrator posts state['script']['scenes'] (plain dicts from JobState JSON). AssemblerRequest declares scene_plans: List[ScenePlan], so Pydantic parses them into ScenePlan instances inside FastAPI — yet main.py, llm_composer.py and duration_prober.py all repeatedly branch `isinstance(x, dict) ... else getattr(...)` (e.g. _plan_field, _scene_value, build_vtt._field, compute_scene_timings). After validation they are always models, never dicts, so all the dict branches in the request-handler path are effectively dead — duplicated dual-mode accessors maintained in 3 modules. The dual-mode is only justified for the unit tests that pass raw dicts directly to compose_html/build_vtt.
- **Evidence:** scenes via FastAPI -> ScenePlan; yet: def _plan_field(plan,key,default=None): return plan.get(...) if isinstance(plan,dict) else getattr(...)  (repeated in 3 files)
- **Fix:** Pick one representation. Either consume ScenePlan models and drop the dict branches in the HTTP path (keep a single shared accessor in shared/ for tests), or type the field as List[Dict]. Consolidate the three near-identical _field/_scene_value/_plan_field helpers into one shared util.

#### F90 — Duplicated forbidden-list logic across sanitizer and validator with no shared source
- **Area:** XCUT-security  |  **Severity:** low  |  **Category:** wrongly-mapped
- **Location:** `services/validator/app/main.py:399-417`
- **Problem:** _FORBIDDEN_MODULES, _FORBIDDEN_BUILTINS, and the invalid-color map are copy-pasted between services/validator/app/main.py and services/code-generator/app/sanitizer.py, and they have already diverged (validator builtins set omits getattr/setattr/delattr/vars/memoryview that the sanitizer lists; the color maps differ in value text). Security-critical denylists living in two places that drift is exactly how a gate weakens silently. This logic belongs in shared/ and should be imported by both.
- **Evidence:** validator _FORBIDDEN_BUILTINS = {eval,exec,compile,__import__,open,breakpoint,memoryview,globals,locals} sanitizer FORBIDDEN_BUILTINS = {eval,exec,compile,__import__,open,breakpoint,memoryview,vars,globals,locals,getattr,setattr,delattr}
- **Fix:** Hoist FORBIDDEN_MODULES / FORBIDDEN_BUILTINS (and the deprecated-name and color maps) into shared/security.py and import them in both services so there is one authoritative denylist. Add a test asserting both services use the same set.

#### F102 — log_render_failure uses CODE_GENERATOR_MODEL as the model for RENDER failures (source='render') — wrong attribution
- **Area:** orchestrator  |  **Severity:** low  |  **Category:** wrongly-mapped
- **Location:** `services/orchestrator/app/core/graph.py:357-363`
- **Problem:** In validator_node, a render failure is logged with model=settings.CODE_GENERATOR_MODEL and source='render'. A render failure is a Manim/HyperFrames execution failure, not an LLM output; tagging it with the code-generator model conflates which model 'produced' the failure for downstream analytics. It may be intentional (the model that wrote the failing code) but the field naming is misleading for source='render' rows.
- **Evidence:** log_render_failure(... attempt=..., error_text=error_log or "render failed", code_text=..., model=settings.CODE_GENERATOR_MODEL, source="render")

## 6. Security Findings

The pipeline executes LLM-generated code, so security is not a side concern. Criticals first.

#### F1 — AST security gate is bypassable: relative imports, attribute-chained access, and aliasing evade the forbidden-module set
- **Area:** voiceover-and-validator  |  **Severity:** critical  |  **Category:** security
- **Location:** `services/validator/app/main.py:399-527`
- **Problem:** _preflight_ast_checks is the ONLY gate before LLM-generated code is executed by `manim render` (which imports and runs construct()). It blocks a hardcoded set of module names and builtins, but the checks are trivially evadable. visit_ImportFrom only flags `node.module.split('.')[0]` in _FORBIDDEN_MODULES, so `from os import system` is caught but `from .os import x` is not, and more importantly indirect access like `__builtins__['ev'+'al']`, `().__class__.__bases__[0].__subclasses__()`, or `getattr(__import__('o'+'s'),'system')` are not caught — `__import__` and `getattr` reachability: `__import__` IS in _FORBIDDEN_BUILTINS but `getattr`, `setattr`, `vars`, `__builtins__` access are NOT. Also `import os as o; o.system(...)` — the Import alias check uses `alias.name.split('.')[0]` which catches `import os as o` (name is 'os'), but `from importlib import import_module` is caught by module root yet `builtins` module itself is not in the forbidden set, so `import builtins; builtins.eval(...)` passes entirely.
- **Evidence:** _FORBIDDEN_MODULES = {"os","subprocess",...} (no "builtins"); _FORBIDDEN_BUILTINS = {"eval","exec","compile","__import__","open",...} (no "getattr","setattr","vars","__builtins__"). visit_ImportFrom: root = node.module.split('.')[0]; if root in _FORBIDDEN_MODULES. A scene doing `import builtins` then `builtins.eval("...")` passes all checks and is then executed by manim.
- **Fix:** Do not rely on AST denylisting for sandboxing untrusted code — it is not a security boundary. Execute manim render in a locked-down sandbox (separate container with no network, read-only FS, dropped caps, seccomp, non-root, ulimits) regardless of AST checks. At minimum add 'builtins' to _FORBIDDEN_MODULES, add getattr/setattr/vars/__builtins__/__subclasses__/__bases__/__class__ to a forbidden-attribute/name set, and reject dunder attribute access. Treat AST as defense-in-depth, not the gate.

#### F13 — detect_content_type defaults Manim on read failure, sending unreadable/binary files into the code-execution path

- **Area:** XCUT-security  |  **Severity:** critical  |  **Category:** security
- **Location:** `services/validator/app/main.py:420-531`
- **Problem:** The validator's _preflight_ast_checks is the ONLY gate on the execution path (code-generator does not run check_manim_security — see separate finding). It is a name-based denylist. It blocks `import os` and `os.system` only when the receiver is a bare Name matching _FORBIDDEN_MODULES. - **Fix:** A denylist AST scan is fundamentally inadequate for running attacker-influenced code. Real fix: execute manim render in a hardened sandbox (gVisor/nsjail/seccomp container, no network, read-only FS, dropped caps, non-root, cgroup memory cap). #### F1 — AST security gate is bypassable: relative imports, attribute-chained access, and aliasing evade the forbidden-module set
- **Area:** voiceover-and-validator  |  **Severity:** critical  |  **Category:** security
- **Location:** `services/validator/app/main.py:399-527`
- **Problem:** _preflight_ast_checks is the ONLY gate before LLM-generated code is executed by `manim render` (which imports and runs construct()). ## 9. Test Gaps (ranked by blast radius)

5. **Segment rename chain** — a voiceover `segments` payload flowing through to a code-gen `audio_cues` cue sheet and a compositor VTT cue.
6. **AssemblerRequest int-key coercion** — assert str-keyed JSON dicts coerce correctly.

## 11. Method, Confidence & Uncertain Findings

**How this was produced.** 18 finder agents (9 per-service maps + 9 cross-cutting audits) generated 334 findings. An adversarial verify pass (one skeptic per finding, instructed to default to "refuted") began; **30 findings were confirmed against source and 10 refuted before the run hit the org monthly spend cap.** The remaining medium/low findings are reported as-mapped but were **not** individually re-verified. Every finding cites `file:line`; the confirmed-30 backbone (all criticals + the top structural highs — admin bypass, sandbox escape, resume int-key, always-404 scene endpoint, retry-cap drift, blocking read, and the pipeline/content-quality roots) were read and confirmed in the source.

**Confidence tiers:**
- **Verified (30):** the criticals and the load-bearing highs in §2/§3/§5/§6.
- **Reported, high-confidence (unverified):** the mediums with concrete code evidence and a clear failure path.
- **Reported, needs-triage:** low-severity weak-points and improvements; treat as a backlog, not a bug list.

**Uncertain (1) — needs human review:**
- `compose_html` per-chunk is passed the **full** `scene_plans`/`image_paths` (only `scene_timings` is the chunk subset). Whether this creates orphan timelines depends on `compose_html` internals not fully traced. Verify a multi-chunk render registers exactly the chunk's timelines. *(`compositor/app/main.py:246`)*

**Refuted (10):** excluded from this document — the verifier read the source and found the claimed defect did not hold (e.g. an "unguarded" path that had an upstream guard, or a severity that overstated blast radius). The remaining unverified mediums/lows will contain a similar false-positive rate; re-verify before acting on any single low-severity item.
